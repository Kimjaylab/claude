# 한국 주식 단타 종목 선별 시스템

코스피/코스닥 종목 중 당일 단타 후보를 스코어링해 매 거래일 09:05경 텔레그램으로 보내는 시스템.

## 현재 진행 상태

- [x] 1단계: 전체 시스템 설계
- [x] 2단계: API 선정 (한국투자증권 KIS Developers + OpenDART)
- [x] 3단계: 폴더 구조 설계
- [x] 4단계: 핵심 모듈 코드 작성 (브로커 어댑터, 데이터, 스크리닝, 스코어링, 알림)
- [ ] 5단계: 테스트 (단위 테스트는 완료, 실계좌 연동 테스트는 API 키 발급 후 진행 필요)
- [ ] 6단계: 백테스트
- [ ] 7단계: 성능 개선
- [ ] 8단계: 최종 완성 (자동화 스케줄링)

## 중요 - 사용 전 반드시 확인할 것

`src/screener/brokers/kis_client.py`의 TR_ID·엔드포인트는 공개 문서/샘플 기준으로 작성했지만,
KIS Developers 포털 공지 없이 바뀔 수 있는 값입니다. **API 키를 발급받으면 모의투자 계좌로
먼저 `get_quote`, `get_volume_rank` 등 개별 함수를 호출해 실제 응답 필드명이 코드와 일치하는지
확인한 뒤 실전에 사용하세요.**

## 설치

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -e ".[dev]"
cp .env.example .env   # 이후 KIS_APP_KEY 등 실제 값 채우기
```

## 테스트 실행

```bash
source .venv/bin/activate
pytest -q
```

API 키가 없어도 `MockClient`로 스코어링/필터 로직 단위 테스트가 전부 통과합니다.

## 수동 실행 (개발 중 확인용)

```bash
source .venv/bin/activate
PYTHONPATH=src python scripts/run_daily.py
```

`.env`에 `KIS_APP_KEY`가 없으면 자동으로 `MockClient`(더미 데이터)로 동작합니다.

## 설정 파일

- `config/settings.yaml`: 스케줄, 유니버스 하한선, 시장 레짐 필터 등 운영 파라미터
- `config/screening_rules.yaml`: 스코어링 가중치. 6단계(백테스트) 완료 후 이 파일의 값을
  최적화 결과로 갱신하는 것이 목표입니다.

## 아키텍처 요약

```
순위분석 API(거래량/등락률/거래대금 상위) → 유니버스 필터(ETF/ETN/관리종목 제외)
  → 정적 필터(전일 종가 기준 추세/돌파) → 동적 필터(당일 실시간 거래량/체결강도/갭)
  → 스코어링(가중합 + 시장레짐 배수) → 리스크 계산(진입/손절/목표가) → 텔레그램 발송
```

## 알려진 제약

- 09:05 발송은 당일 데이터가 5분치뿐이라 노이즈가 있습니다. 필요 시 09:30 재확인 스캔을
  추가하는 것을 권장합니다(아직 미구현).
- 노트북(맥북) 자동 실행 시 기기가 잠들어 있으면 스케줄이 동작하지 않습니다. `pmset`으로
  예약 기상을 설정하거나 상시 구동 서버로 이전하는 것을 8단계에서 다룰 예정입니다.
- 종목마스터 파일의 정확한 컬럼 오프셋은 실제 파일로 검증되지 않았습니다(`data/universe.py`).
  실패 시 이름 기반 휴리스틱으로 자동 폴백하지만, 실전 사용 전 검증을 권장합니다.
